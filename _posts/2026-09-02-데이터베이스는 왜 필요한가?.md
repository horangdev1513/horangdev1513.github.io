### 한 줄 요약
> 데이터베이스(DB)는 구조화된 데이터의 집합이다. 이것을 여러 사용자가 안전하고 일관되게 저장·조회·수정할 수 있게 관리해 주는 소프트웨어가 DBMS다.

---

### 왜 필요한가?

**1. 여러 사용자가 동시에 읽고 써도 데이터가 깨지지 않는다 (동시성)**
CSV 파일을 두 사람이 동시에 열어 수정하면, 나중에 저장한 사람이 앞사람의 작업을 그대로 덮어쓴다. DB는 누가 언제 무엇을 바꾸는지 통제해서 이 충돌을 막는다.

**2. 규칙(제약 조건)에 어긋난 데이터는 저장 자체가 거부된다 (일관성 · 무결성)**
파일에는 나이 칸에 -5가, 존재하지 않는 회원의 주문이 아무 경고 없이 들어간다. DB는 저장하는 순간 제약 조건을 검사해서 잘못된 데이터를 거절한다.

**3. 데이터가 저장되는 방식이 바뀌어도 프로그램은 수정하지 않아도 된다 (독립성)**
파일의 저장 구조를 바꾸면 그 파일을 읽던 코드를 전부 고쳐야 한다. DB는 "어떻게 저장하는지"와 "어떻게 꺼내 쓰는지"를 분리해서, 내부 구조가 바뀌어도 쿼리는 그대로다.

---

### 핵심 개념

**데이터베이스(DB) vs DBMS(Database Management System)**
- 데이터베이스(DB) : 체계화된 데이터들의 모음
- DBMS(Database Management System) : 데이터들을 저장,관리 조작 하기 위한 소프트웨어 (PostgreSQL, MySQL, Oracle ...)

**스키마 vs 데이터**
- 스키마 : 데이터를 어떤 모양으로 저장할지 정한 설계도 (테이블, 컬럼, 타입, 제약 조건) / 자주 바뀌지 않는다
- 데이터 : 그 설계도 안에 실제로 들어 있는 값 / 자주 바뀐다

**쿼리(Query)**
- 사용자나 프로그램이 DBMS에 "데이터를 꺼내줘 / 바꿔줘"라고 요청하는 문장
- 관계형 DB에서는 SQL을 쓴다.

---

### 예시

회원 정보를 MySQL에 저장한다고 하자.

```sql
CREATE TABLE users (
  id    INT PRIMARY KEY,
  name  VARCHAR(50) NOT NULL,
  age   INT CHECK (age >= 0)
);

SELECT name FROM users WHERE age >= 20;
```

- MySQL → **DBMS**
- `users` 테이블의 컬럼·타입·제약 조건 → **스키마**
- `CHECK (age >= 0)` 덕분에 나이에 -5는 들어갈 수 없다 → **무결성**
- `SELECT ...` → **쿼리**
- 이 테이블에 실제로 쌓이는 행들 → **데이터(베이스)**

### 정리
- 데이터베이스(DB)는 구조화된 데이터의 집합이고, 그것을 관리하는 소프트웨어가 DBMS다. MySQL·PostgreSQL은 데이터베이스가 아니라 DBMS다.
- DBMS 덕분에 여러 사용자가 데이터를 동시에, 일관되게, 장애에도 안전하게, 저장 방식과 무관하게 다룰 수 있다.
